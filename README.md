# NLP Text-to-SQL Generator

Convert natural-language questions into Microsoft SQL Server (T-SQL) queries using a fine-tuned **FLAN-T5-Small** model.

The project includes a model-training script, a command-line interface, and a Streamlit web interface. Generated SQL is checked for syntax and selected query-intent requirements, with rule-based repair attempts for a few common cases.

## Features

- **Natural-language to SQL:** Generate SQL queries from questions written in plain English.
- **Fine-tuned transformer:** Uses `google/flan-t5-small` as the base sequence-to-sequence model.
- **Schema-aware prompting:** Pass table names and column names along with the question.
- **SQL syntax validation:** Uses SQLGlot with the `tsql` dialect to parse generated queries.
- **Basic semantic checks:** Checks for selected expected clauses such as `WHERE`, `COUNT`, `TOP`, and `JOIN`.
- **Rule-based repair:** Attempts to repair certain detected omissions.
- **Two ways to use the project:** A command-line interface and a Streamlit interface.
- **GPU support:** Uses CUDA when available and otherwise runs on CPU.

## Workflow

1. Prepare training examples in `students_dataset.json`.
2. Load the dataset and split it into training and validation subsets.
3. Fine-tune `google/flan-t5-small` on natural-language questions and their SQL outputs.
4. Save the trained model and tokenizer to `fine_tune_model/`.
5. Enter a natural-language question and the relevant table schema.
6. Generate a SQL query using the fine-tuned model.
7. Validate the generated query with SQLGlot and perform the implemented semantic checks.
8. If a supported issue is detected, attempt a rule-based repair and display the resulting query.

## Setup and Installation

### 1. Clone the repository

```bash
git clone https://github.com/bruce17022006/NLP_TEXT_TO_SQL.git
cd NLP_TEXT_TO_SQL
```

### 2. Create and activate a virtual environment

**Windows**

```bash
python -m venv venv
venv\Scripts\activate
```

**macOS / Linux**

```bash
python3 -m venv venv
source venv/bin/activate
```

### 3. Install dependencies

```bash
pip install torch transformers datasets streamlit sqlglot sentencepiece
```

> Install the PyTorch build appropriate for your system and CUDA version if you want GPU acceleration. The project can also run on CPU, although training and inference may be slower.

## Train the Model

Make sure `students_dataset.json` is present in the project root, then run:

```bash
python train.py
```

The training script fine-tunes `google/flan-t5-small` and saves the resulting model and tokenizer in:

```text
fine_tune_model/
```

Run training before launching either application if the trained model directory is not already available.

## Run the Application

### Option 1: Streamlit Web Interface

```bash
streamlit run app_ui.py
```

Open the local URL printed in the terminal by Streamlit. Enter:
- A natural-language question.
- The table schema, with one table per line.

Example schema:

```text
Students: id, name, dept_id
Departments: dept_id, name
```

Example question:

```text
Get the student names and their department names
```

Click **Generate & Repair SQL** to view the generated query.

### Option 2: Command-Line Interface

```bash
python app.py
```

Enter a natural-language question, then provide the schema one line at a time. Submit an empty line to finish entering the schema.

## Important Notes and Limitations

- The repository expects a trained model at `./fine_tune_model`. The model directory is generated by running `train.py`; it is not listed among the repository's currently committed files.
- The training script downloads the base FLAN-T5-Small model through Hugging Face Transformers, so internet access is needed the first time unless the model is already cached.
- SQLGlot checks whether the generated query can be parsed as T-SQL. Successful parsing does not guarantee that the query is logically correct or executable against a real database.
- Semantic checks and automatic repairs cover selected patterns in the current implementation; they are not a general SQL reasoning or repair system.
- The current JOIN repair uses `dept_id` as the assumed common key. Review repaired queries against your actual database schema before execution.
- This project generates SQL text; it does not connect to or execute queries against a database.
